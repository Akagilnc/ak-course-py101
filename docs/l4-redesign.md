## 章节页

`#1 从 JSON 到文件`

How to read JSON and save reports?

L3 看过接口返回的 JSON；L4 直接读取本地 JSON 文件。

## 认识 lesson4.json

先打开文件看结构，不急着写代码。

```json
{
    "data_title": "fymap",
    "data": {
        "mtime": "2020-10-05 21:01:00",
        "othertotal": {
            "certain": "35270206",
            "die": "1036359",
            "recure": "26340847",
            "ecertain": "7893000"
        }
    }
}
```

实际文件里内容很多，但前半只关心这条路径：

```python
raw_data["data"]["othertotal"]
```

### 字段说明

- `mtime`：数据更新时间。
- `othertotal`：海外疫情汇总。
- `certain`：累计确诊。
- `die`：累计死亡。
- `recure`：累计治愈。
- `ecertain`：现存确诊。

## 前置知识：读取 JSON 文件

```python
import json

file = open("lesson4.json", encoding="utf-8")
raw_data = json.load(file)
file.close()
```

讲解重点：

- `import json`：把 JSON 工具拿进来。
- `open("lesson4.json", encoding="utf-8")`：打开本地 JSON 文件。
- `json.load(file)`：从文件里读取 JSON，并转成 Python 的 dict / list。
- 这里是 `json.load(file)`，L3 API 那里是 `json.loads(text)`；一个读文件，一个读字符串。

## 找到 total 数据

```python
data = raw_data["data"]
total = data["othertotal"]

print(total["certain"])
print(total["die"])
print(total["recure"])
print(total["ecertain"])
```

标准输出：

```text
35270206
1036359
26340847
7893000
```

所以呢：

- JSON 文件读进来以后，不需要切字符串。
- 只要路径找对，就可以像读字典一样读字段。
- `total` 是一个小 dict，第一次上手先处理它，不进入更深的国家列表。

## 第一步：保存海外疫情汇总到 txt

### 目标

从 `lesson4.json` 里取出海外汇总数据，生成一段可以直接读的文字，写入 `l4_oversea_report.txt`。

### 第一步代码

```python
import json

file = open("lesson4.json", encoding="utf-8")
raw_data = json.load(file)
file.close()

data = raw_data["data"]
time = data["mtime"]
total = data["othertotal"]

reports = []
reports.append("截至{}，海外疫情汇总：\n".format(time))
reports.append("累计确诊 {} 例\n".format(total["certain"]))
reports.append("现存确诊 {} 例\n".format(total["ecertain"]))
reports.append("累计死亡 {} 例\n".format(total["die"]))
reports.append("累计治愈 {} 例\n".format(total["recure"]))

file = open("l4_oversea_report.txt", "w", encoding="utf-8")
file.writelines(reports)
file.close()
```

### 运行后得到的 `l4_oversea_report.txt`

```text
截至2020-10-05 21:01:00，海外疫情汇总：
累计确诊 35270206 例
现存确诊 7893000 例
累计死亡 1036359 例
累计治愈 26340847 例
```

### Recap

- `json.load(file)` 负责把 JSON 文件读成 Python 数据。
- `raw_data["data"]["othertotal"]` 是这次最关键的路径。
- `reports` 仍然是 L3 的老办法：先把文字放进 list，再一次性写入文件。
- `txt` 适合给人读，但不适合继续排序、筛选、做表格处理。

## 后半模块 1：微信群报名接龙

### 目标

前半的 `lesson4.json` 好处理，是因为它已经有字段。现实里的报名信息通常没有这么规整。

这个案例让学生看到：人能看懂，不等于程序能直接处理。程序和 AI 都需要字段、规则和边界。

### 原始数据

```text
张三 成都 13800001111
李四-成都市-13900002222
王五，成都高新区，13700003333
赵六 重庆 13600004444
张三 成都 13800001111
小王 13500005555
```

### 先观察问题

这几行数据看起来不难，但对程序来说有很多麻烦：

- 分隔符不统一：空格、短横线、中文逗号混在一起。
- 城市写法不统一：`成都`、`成都市`、`成都高新区`。
- 有重复报名：`张三 成都 13800001111` 出现两次。
- 有信息缺失：`小王 13500005555` 没有城市。
- 有些判断需要人定规则：`成都高新区` 算不算成都？

### 课堂讨论

- 小王没有城市，这条要不要保留？
- 成都高新区算成都，还是单独算一个区域？
- 张三重复报名，是直接删掉后一个，还是标记出来人工确认？
- 如果手机号重复但姓名不同，应该自动合并吗？

### 结构化以后可能长这样

| 姓名 | 原始城市 | 标准城市 | 手机号 | 备注 |
| --- | --- | --- | --- | --- |
| 张三 | 成都 | 成都 | 13800001111 | 重复报名，需要确认 |
| 李四 | 成都市 | 成都 | 13900002222 | 城市名称已标准化 |
| 王五 | 成都高新区 | 成都 | 13700003333 | 是否单独统计高新区取决于口径 |
| 赵六 | 重庆 | 重庆 | 13600004444 | - |
| 小王 | 缺失 | 缺失 | 13500005555 | 缺少城市，不能自动补全 |

### AI 插入点：让 AI 帮忙结构化

不好的提问方式：

```text
帮我整理一下这些报名信息。
```

更好的提问方式：

```text
请把下面的报名信息整理成表格，字段包括：姓名、城市、手机号、标准城市、备注。

要求：
1. 不要自行补全缺失信息
2. 重复报名请标记出来，不要直接删除
3. 城市名称先保留原文，再给出标准城市
4. 无法判断的地方写在备注里

原始数据：
张三 成都 13800001111
李四-成都市-13900002222
王五，成都高新区，13700003333
赵六 重庆 13600004444
张三 成都 13800001111
小王 13500005555
```

### 所以呢

- JSON 好处理，是因为它已经有字段。
- 微信接龙难处理，是因为字段还藏在乱文本里。
- AI 可以帮你从乱文本整理出表格，但要明确要求它保留缺失、重复和不确定。
- 现实数据进入程序前，第一步往往不是计算，而是结构化。

## 后半模块 2：奶茶店订单

### 目标

前半把几个指标做成了 Excel 表。这个案例用一张更生活化的小表，让学生理解：表格数据不是只用来保存，还可以用来提出问题。

### 原始数据

```text
珍珠奶茶，单价12，销量3
柠檬茶，单价10，销量4
拿铁，单价18，销量2
```

换成表格：

| 商品 | 单价 | 销量 |
| --- | ---: | ---: |
| 珍珠奶茶 | 12 | 3 |
| 柠檬茶 | 10 | 4 |
| 拿铁 | 18 | 2 |

### 先看三个问题

- 哪个产品销量最高？
- 哪个产品单价最高？
- 哪个产品销售额最高？

简单算一下：

| 商品 | 单价 | 销量 | 销售额 |
| --- | ---: | ---: | ---: |
| 珍珠奶茶 | 12 | 3 | 36 |
| 柠檬茶 | 10 | 4 | 40 |
| 拿铁 | 18 | 2 | 36 |

### 反直觉点

- 销量最高：柠檬茶，4 杯。
- 单价最高：拿铁，18 元。
- 销售额最高：柠檬茶，40 元。

卖得最多、单价最高、销售额最高，不一定是同一个商品。

### 课堂讨论

- 如果你是店长，最关心销量、销售额，还是利润？
- 如果要决定明天备货，只看今天销量够不够？
- 如果想知道哪个产品最赚钱，还缺什么数据？

### AI 插入点：让 AI 帮你提出问题

```text
请根据下面这份奶茶店订单数据，提出 5 个值得分析的问题。

要求：
1. 区分“可以直接从数据回答”和“需要更多数据才能回答”
2. 每个问题说明为什么值得问
3. 不要直接给经营建议

数据：
珍珠奶茶，单价12，销量3
柠檬茶，单价10，销量4
拿铁，单价18，销量2
```

可能得到的方向：

```text
可以直接回答：
- 哪个产品销量最高？
- 哪个产品销售额最高？
- 总销售额是多少？

需要更多数据：
- 哪个产品利润最高？因为目前没有成本数据。
- 明天应该多备什么？因为还需要历史销量和库存数据。
```

### 所以呢

- 数据分析不是先把所有数字算出来，而是先问对问题。
- 同一张表，不同问题会看不同字段。
- AI 不只是回答问题，也可以帮你提出问题、区分哪些问题现在能回答，哪些问题还缺数据。
- 下一节 pandas 做的很多事，本质上就是更快地筛选、计算、统计和导出表格。

## 备用模块：消费流水分类

一堆消费记录，怎样变成“这个月钱花在哪儿了”？

这个案例轻、生活化，适合让学生现场说分类，不需要写代码。

### 原始数据

```text
2026-05-18 星巴克 32
2026-05-18 地铁 5
2026-05-18 罗森便利店 18
2026-05-19 京东图书 89
2026-05-19 美团外卖 42
2026-05-20 盒马鲜生 76
2026-05-20 滴滴出行 23
2026-05-21 网易云音乐会员 15
```

### 先问学生

- 哪一笔最大？
- 哪几笔是交通？
- 哪几笔是吃喝？
- 如果要做月度支出统计，类别怎么分？

### 分类争议点

- 星巴克算餐饮，还是饮品，还是休闲？
- 盒马鲜生算生鲜、生活用品，还是餐饮？
- 京东图书算购物，还是学习？
- 网易云音乐会员算娱乐，还是订阅服务？

这些问题没有天然唯一答案，取决于统计目的。

### AI 插入点：让 AI 帮忙分类，但标记不确定

```text
请把下面的消费流水整理成表格，字段包括：日期、商户、金额、建议分类、备注。

要求：
1. 不要编造原始数据里没有的信息
2. 分类不确定的地方，请在备注里说明
3. 对可能有多种分类的记录，给出两个候选分类
4. 最后列出一套你建议采用的分类规则

消费流水：
2026-05-18 星巴克 32
2026-05-18 地铁 5
2026-05-18 罗森便利店 18
2026-05-19 京东图书 89
2026-05-19 美团外卖 42
2026-05-20 盒马鲜生 76
2026-05-20 滴滴出行 23
2026-05-21 网易云音乐会员 15
```

### 可能得到的方向

```text
星巴克：餐饮 / 饮品，存在轻微口径差异。
地铁：交通。
罗森便利店：便利店 / 生活用品 / 零食，需要看购买内容。
京东图书：学习 / 购物，取决于统计目的。
美团外卖：餐饮。
盒马鲜生：生鲜 / 生活用品 / 餐饮，需要看购买内容。
滴滴出行：交通。
网易云音乐会员：娱乐 / 订阅服务。
```

### 所以呢

- AI 可以帮你快速分类，但分类规则不是客观真理。
- 你要先告诉它：我是为了记账、控制餐饮支出、统计学习投入，还是做报销？
- 目标不同，分类就可能不同。
- 数据分类，本质上是把现实世界按某种目的重新切一遍。

### pandas 预告

如果有几百条消费记录，pandas 可以按分类汇总金额：

```python
df.groupby("分类")["金额"].sum()
```

这里不展开讲，只让学生知道：后面会有工具专门做这种批量汇总。

## 后半模块 3：天气 API

### 目标

这个案例把 API 放回来，但换成比股票更轻的生活场景：明天晚上有户外活动，要不要提醒大家带伞？

重点不是让学生写 API 代码，而是让他们看懂：API 返回的不是网页，而是一包结构化数据。我们要从里面找到能回答问题的字段。

### API 返回的数据

```json
{
  "city": "成都",
  "date": "2026-05-20",
  "forecast": [
    {
      "time": "09:00",
      "temperature": 22,
      "rain_probability": 20,
      "wind": "微风"
    },
    {
      "time": "15:00",
      "temperature": 27,
      "rain_probability": 65,
      "wind": "微风"
    },
    {
      "time": "21:00",
      "temperature": 23,
      "rain_probability": 80,
      "wind": "小风"
    }
  ]
}
```

### 先看结构

- 最外层是一个 dict。
- `city` 是城市。
- `date` 是日期。
- `forecast` 是一个 list。
- `forecast` 里面每一条，是一个时间点的天气记录。

这和前半的 JSON 路径是同一种思路，只是这次的路径更像：

```python
weather["forecast"][0]["rain_probability"]
```

### 课堂问题

- 如果你明天上午出门，要不要带伞？
- 如果明天下午出门，要不要带伞？
- 如果晚上 8 点有户外活动，要不要提前提醒大家？
- 如果只看上午天气，会不会误判？

### 数据判断

```text
09:00 降雨概率 20%，风险不高。
15:00 降雨概率 65%，风险明显升高。
21:00 降雨概率 80%，晚上户外活动风险较高。
```

反直觉点：同一天的天气，不同时间段结论可能完全不同。

### AI 插入点：让 AI 把 API 数据变成活动提醒

```text
下面是一段天气 API 返回的数据。

请根据数据写一段“活动提醒”，场景是：明天晚上 8 点有户外活动。

要求：
1. 只根据给定数据，不要编造天气原因
2. 明确说明你主要参考的是哪个时间点的数据
3. 如果数据不足，请说明还缺什么
4. 输出分成：结论、依据、提醒

数据：
{
  "city": "成都",
  "date": "2026-05-20",
  "forecast": [
    {"time": "09:00", "temperature": 22, "rain_probability": 20, "wind": "微风"},
    {"time": "15:00", "temperature": 27, "rain_probability": 65, "wind": "微风"},
    {"time": "21:00", "temperature": 23, "rain_probability": 80, "wind": "小风"}
  ]
}
```

### 可能得到的输出

```text
结论：
明晚户外活动有较高下雨风险，建议提前准备雨具，必要时考虑备用室内方案。

依据：
活动时间接近 21:00，该时间点降雨概率为 80%，明显高于上午和下午。

提醒：
目前只有 09:00、15:00、21:00 三个时间点，没有更精细的小时预报，也没有降雨量信息，所以只能判断“风险偏高”，不能判断一定会下雨。
```

### 所以呢

- API 数据不是直接给人读的，它通常是给程序读的。
- 人要先问：我要解决什么问题？要看哪个字段？要看哪个时间点？数据够不够支持这个结论？
- AI 可以帮你把结构化数据变成提醒，但不能替你决定数据够不够。
- 80% 降雨概率不是“一定下雨”，报告里不能说过头。

## 后半 Recap

- 现实信息要先变成字段、记录和表格，程序才容易处理。
- JSON 好处理，是因为它已经结构化；接龙、流水、订单这些现实数据，常常需要先整理。
- 同一张表可以回答很多问题，但先要问清楚你想知道什么。
- 指标不同，结论可能不同；销量、单价、销售额不是一回事。
- 分类不是天然存在的，是按目的定规则。
- API 返回的数据通常是给程序读的，要先找到关键字段，再做判断。
- AI 可以帮忙结构化、提出问题、分类、改写提醒，但要给它边界。
- 程序负责稳定处理数据，AI 负责帮助理解、表达和补全思路，口径和边界仍然由人决定。

## L5 铺垫

前半我们用 `DataFrame` 把几行汇总指标保存成 Excel。后半几个案例都在说明一件事：现实里的数据一旦变成表格，就可以继续筛选、计算、分类、汇总和导出。

下一节开始，pandas 会正式登场，专门处理这些更大的表：

- 多行数据，不用手写很多 `for`。
- 多个字段，可以快速筛选和计算。
- 可以按分类汇总，比如商品、城市、消费类别。
- 可以导出 Excel，让结果变成可交付文件。

可以提前露一眼，不展开讲：

```python
df.groupby("分类")["金额"].sum()
```

这句话以后会经常出现。它的意思是：按分类汇总金额。
