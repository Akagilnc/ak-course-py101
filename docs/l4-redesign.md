# L4

## 定位

L4 的前半主题：读取 JSON 文件，把结构化数据变成可保存的报告。

L3 已经看过 API 返回的 JSON，也讲过 dict / list 的取值。L4 把这件事落到本地文件：打开 `lesson4.json`，找到海外疫情汇总数据，先保存成 `txt`，再保存成 `xlsx`。

- 输入：本地 `lesson4.json`。
- 读取：`json.load(file)` 把 JSON 文件变成 Python 数据。
- 取值：用 dict / list 的方式找到 `data -> othertotal`。
- 输出：第一步写入 `l4_oversea_report.txt`，第二步写入 `l4_oversea_report.xlsx`。
- 课堂重点：JSON 不是新魔法，本质还是 dict 和 list；文件输出可以从纯文字走到表格。

## 章节页

`#1 从 JSON 到文件`

How to read JSON and save reports?

L3 看过接口返回的 JSON；L4 直接读取本地 JSON 文件。

## 认识 lesson4.json

先打开文件看结构，不急着写代码。

```json
{
    "data_title": "fymap",
    "data": {
        "mtime": "2020-10-05 21:01:00",
        "othertotal": {
            "certain": "35270206",
            "die": "1036359",
            "recure": "26340847",
            "ecertain": "7893000"
        }
    }
}
```

实际文件里内容很多，但前半只关心这条路径：

```python
raw_data["data"]["othertotal"]
```

### 字段说明

- `mtime`：数据更新时间。
- `othertotal`：海外疫情汇总。
- `certain`：累计确诊。
- `die`：累计死亡。
- `recure`：累计治愈。
- `ecertain`：现存确诊。

## 前置知识：读取 JSON 文件

```python
import json

file = open("lesson4.json", encoding="utf-8")
raw_data = json.load(file)
file.close()
```

讲解重点：

- `import json`：把 JSON 工具拿进来。
- `open("lesson4.json", encoding="utf-8")`：打开本地 JSON 文件。
- `json.load(file)`：从文件里读取 JSON，并转成 Python 的 dict / list。
- 这里是 `json.load(file)`，L3 API 那里是 `json.loads(text)`；一个读文件，一个读字符串。

## 找到 total 数据

```python
data = raw_data["data"]
total = data["othertotal"]

print(total["certain"])
print(total["die"])
print(total["recure"])
print(total["ecertain"])
```

标准输出：

```text
35270206
1036359
26340847
7893000
```

所以呢：

- JSON 读进来以后，不需要像普通文本那样自己切字符串。
- 只要路径找对，就能直接按字段名取值，比如 `certain`、`die`、`recure`。
- `total` 是一个小 dict，适合第一次上手：字段少、路径短，能先把“从结构里取数据”这件事跑通。

## 第一步：保存海外疫情汇总到 txt

### 目标

从 `lesson4.json` 里取出海外汇总数据，生成一段可以直接读的文字，写入 `l4_oversea_report.txt`。

### 第一步代码

```python
import json

file = open("lesson4.json", encoding="utf-8")
raw_data = json.load(file)
file.close()

data = raw_data["data"]
time = data["mtime"]
total = data["othertotal"]

reports = []
reports.append("截至{}，海外疫情汇总：\n".format(time))
reports.append("累计确诊 {} 例\n".format(total["certain"]))
reports.append("现存确诊 {} 例\n".format(total["ecertain"]))
reports.append("累计死亡 {} 例\n".format(total["die"]))
reports.append("累计治愈 {} 例\n".format(total["recure"]))

file = open("l4_oversea_report.txt", "w", encoding="utf-8")
file.writelines(reports)
file.close()
```

### 运行后得到的 `l4_oversea_report.txt`

```text
截至2020-10-05 21:01:00，海外疫情汇总：
累计确诊 35270206 例
现存确诊 7893000 例
累计死亡 1036359 例
累计治愈 26340847 例
```

### Recap

- `json.load(file)` 负责把 JSON 文件读成 Python 数据。
- `raw_data["data"]["othertotal"]` 是这次最关键的路径。
- `reports` 仍然是 L3 的老办法：先把文字放进 list，再一次性写入文件。
- `txt` 适合给人读，但不适合继续排序、筛选、做表格处理。

### 前置知识：DataFrame

```python
import pandas as pd

total = {
    "certain": "35270206",
    "ecertain": "7893000",
    "die": "1036359",
    "recure": "26340847",
}

df = pd.DataFrame([total])

df.to_excel("l4_oversea_report.xlsx", index=False, sheet_name="汇总")
```

讲解重点：

- `pd` 是 `pandas` 的常用简称。
- `df` 是这张表，先理解成“Python 里的 Excel 表格”。
- `[total]`：把一个 dict 当成表格里的一行。
- `to_excel("文件名.xlsx")`：保存成 Excel 文件。
- `index=False`：不保存自动生成的行号。
- `sheet_name="汇总"`：设置工作表名称。

## 第二步代码

```python
import json
import pandas as pd

file = open("lesson4.json", encoding="utf-8")
raw_data = json.load(file)
file.close()

data = raw_data["data"]
total = data["othertotal"]

df = pd.DataFrame([total])

df.to_excel("l4_oversea_report.xlsx", index=False, sheet_name="汇总")
```

### 运行后得到的 Excel

文件名：

```text
l4_oversea_report.xlsx
```

表格内容：

| certain | ecertain | die | recure |
| ---: | ---: | ---: | ---: |
| 35270206 | 7893000 | 1036359 | 26340847 |

### Recap

- `txt` 是文字报告，适合直接阅读。
- `xlsx` 是表格报告，适合继续加工。
- 代码前半段没有变：还是读取 JSON，找到 `total`。
- `DataFrame([total])` 把 dict 变成一行表格。
- 输出方式变了：从 `writelines()` 换成 `to_excel()`。

  - 如果明天要主推，只看利润够不够？

### H10：算出毛利

- 页面类型：`table-card`
- eyebrow：`看赚钱能力`
- h2：`再看每款大概赚了多少`
- 表格：

| 商品 | 单杯毛利 | 销量 | 总毛利 | 制作分钟 | 原料状态 |
| --- | ---: | ---: | ---: | ---: | --- |
| 珍珠奶茶 | 7 | 38 | 266 | 3 | 偏紧 |
| 柠檬茶 | 7 | 52 | 364 | 2 | 正常 |
| 拿铁 | 9 | 21 | 189 | 5 | 充足 |
| 芋泥波波 | 8 | 30 | 240 | 4 | 偏紧 |

- mini-note：`单杯毛利 = 单价 - 成本；总毛利 = 单杯毛利 × 销量。`

### H11：问题页

- 页面类型：`question-list tight`
- eyebrow：`店长真正关心什么`
- h2：`主推不是简单看最大值`
- 问题：
  - 柠檬茶总毛利最高，是不是就一定主推它？
  - 珍珠奶茶总毛利也不错，但原料偏紧，意味着什么？
  - 拿铁单杯毛利最高，为什么总毛利反而不高？
  - 如果明天下雨或降温，这份判断会不会变？

### H12：AI 插入页

- 页面类型：`photo-slide prompt-box`
- eyebrow：`AI 可以帮哪一步？`
- h2：`帮老板做一版主推建议`
- prompt：

```text
请根据下面这份奶茶店数据，帮老板分析明天主推哪一款。

要求：
1. 先比较单杯毛利和总毛利
2. 不只看销量，也要考虑制作时间和原料状态
3. 给出一个主推建议和一个备选
4. 说明这个建议还缺哪些数据

数据：
珍珠奶茶，单价12，成本5，销量38，制作3分钟，原料偏紧
柠檬茶，单价10，成本3，销量52，制作2分钟，原料正常
拿铁，单价18，成本9，销量21，制作5分钟，原料充足
芋泥波波，单价16，成本8，销量30，制作4分钟，原料偏紧
```

### H13：AI 输出方向

- 页面类型：`output report-example`
- eyebrow：`可能得到的方向`
- h2：`AI 的价值是把多个指标合在一起看`
- 内容：

```text
从总毛利看，柠檬茶最高：单杯毛利 7 元，销量 52 杯，总毛利 364 元。
从执行难度看，柠檬茶制作时间短，原料状态正常，比原料偏紧的珍珠奶茶和芋泥波波更适合主推。

建议主推：柠檬茶。
备选：珍珠奶茶，但要先确认原料是否够。

还缺的数据：历史销量、天气、客流时间段、库存数量。
```

### H14：所以呢

- 页面类型：`ul`
- eyebrow：`所以呢`
- h2：`这张表帮我们看清了什么？`
- 要点：
  - 原始表只能看到单价、成本、销量；它还不能直接回答“明天主推哪一款”。
  - 算出毛利以后，才会发现“卖得多”和“赚得多”可能不是同一回事。
  - 加入制作时间和原料状态以后，主推选择就不再是看最大值，而是看利润、效率和备货风险。
  - AI 可以帮忙整理比较思路，但前提是字段清楚，问题也问得清楚。
  - pandas 后面会把这些计算、筛选、统计和导出变得更快。

df.groupby("分类")["金额"].sum()

## 案例 4：天气 API

### H20：案例目标

- 页面类型：`step-ladder`
- eyebrow：`案例 4 · 天气 API`
- h2：`结构化数据变成生活提醒`
- 三行：
  - `场景`：明天晚上有户外活动，要不要提醒大家带伞？
  - `数据`：API 返回一段 JSON，不是网页。
  - `目标`：找到关键字段，做不过度的判断。

### H21：API 返回数据

- 页面类型：`quiz-full-code` 或 `output report-example`
- eyebrow：`API 返回的数据`
- h2：`程序拿到的是 JSON`
- 内容：

```json
{
  "city": "成都",
  "date": "2026-05-20",
  "forecast": [
    {"time": "09:00", "temperature": 22, "rain_probability": 20},
    {"time": "15:00", "temperature": 27, "rain_probability": 65},
    {"time": "21:00", "temperature": 23, "rain_probability": 80}
  ]
}
```

### H22：看结构

- 页面类型：`step-ladder`
- eyebrow：`先看结构`
- h2：`路径仍然是 dict 和 list`
- 四行：
  - `city`：城市，成都。
  - `date`：日期，2026-05-20。
  - `forecast`：一个 list，里面每条是一个时间点。
  - `路径`：`weather["forecast"][0]["rain_probability"]`

### H23：课堂问题

- 页面类型：`question-list tight`
- eyebrow：`课堂问题`
- h2：`同一天，不同时间段结论可能不同`
- 问题：
  - 上午出门，要不要带伞？
  - 下午出门，要不要带伞？
  - 晚上 8 点有户外活动，要不要提前提醒大家？
  - 如果只看上午天气，会不会误判？

### H24：数据判断

- 页面类型：`output report-example`
- eyebrow：`数据判断`
- h2：`看哪个字段，取决于问题`
- 内容：

```text
09:00 降雨概率 20%，风险不高。
15:00 降雨概率 65%，风险明显升高。
21:00 降雨概率 80%，晚上户外活动风险较高。
```

### H25：AI 插入页

- 页面类型：`photo-slide`，建议分两页也可以：天气数据一页，任务 prompt 一页。
- eyebrow：`AI 可以帮哪一步？`
- h2：`把结构化数据改写成活动提醒`
- prompt：

```text
请写一段活动提醒：明天晚上 8 点有户外活动。

要求：
1. 只根据给定数据
2. 说明主要参考哪个时间点
3. 数据不足就说明缺什么
4. 输出：结论、依据、提醒
```

### H26：参考输出

- 页面类型：`output report-example`
- eyebrow：`参考输出`
- h2：`把数据变成可以发给人的话`
- 内容：

```text
结论：
明晚户外活动有较高下雨风险，建议提前准备雨具。

依据：
活动时间接近 21:00，该时间点降雨概率为 80%。

提醒：
目前只有三个时间点，没有更精细的小时预报，也没有降雨量信息，所以只能判断风险偏高。
```

### H27：所以呢

- 页面类型：`ul`
- eyebrow：`所以呢`
- h2：`API 数据能支持提醒，但不能支持过度结论`
- 要点：
  - API 数据通常是给程序读的，人要先找到和问题有关的字段。
  - 晚上活动就重点看接近活动时间的降雨概率，而不是只看上午天气。
  - 80% 降雨概率适合支持“提前准备雨具或改室内方案”，不是把提醒写成绝对断言。
  - 数据不足时，提醒里要说清楚还缺什么，比如更细时间预报、降雨量、活动地点。

## 后半 Recap

### H28：后半 Recap

- 页面类型：`ul`
- eyebrow：`后半 Recap`
- h2：`现实信息进入程序前，需要先变成结构`
- 要点：
  - 接龙、流水、订单这些现实数据，常常要先整理成字段。
  - 同一张表可以回答很多问题，但先要问清楚想知道什么。
  - 分类不是天然存在的，是按目的定规则。
  - API 返回的数据通常是给程序读的，要先找到关键字段。
  - AI 可以帮忙结构化、提问题、分类、改写提醒，但边界仍然由人决定。

## 给 Codex 的实现要求

更新 `docs/l4-slides.html` 时遵守以下要求：

1. 不改 L4 前半 quiz 和前半动手部分，除非只是修错别字或明显排版问题。
2. 将原后半替换为上面 H0-H28 的节奏结构。
3. 页面风格尽量复用现有 L4 / L2 样式：`center`、`step-ladder`、`question-list tight`、`table-card`、`photo-slide`、`prompt-box`、`output report-example`。
4. HTML 中不要出现“备用模块”“时间够再讲”“给 Codex”这类备课字样。
5. AI 页要像课堂演示，不要像 prompt 教程。每个 AI 页都要让学生看出“AI 在数据流程中帮哪一步”。
6. 表格页优先使用 `table-card`，不要用长段列表模拟表格。
7. 每页尽量只承担一个作用：目标、数据、问题、判断、AI、所以呢，不要一页塞两三个功能。
8. 后半内容可以略多，老师现场可以口头跳过；不需要在 HTML 里标记可跳过。
9. 保持现有键盘翻页逻辑和整体视觉主题。
