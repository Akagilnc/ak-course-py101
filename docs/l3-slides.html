#1 从数据到报告

How to turn data into a report?

L2 已经能批量计算；L3 让结果变成给人看的文字。

前半目标

从程序输出，到可读报告

程序结果

名称、行业、涨跌额、涨跌幅。

可读报告

贵州茅台（白酒）今日下跌 4 元，跌幅 0.23%。

任务规则

今天要做一份股票风险报告

输入几只股票的名称、行业、开盘价、收盘价。
计算每只股票的涨跌额和涨跌幅。
筛选只保留下跌股票，作为风险提示。
输出显示报告，并保存成文件。

手动输入的数据

先用一张很小的虚拟表

stocks = [

    ["比亚迪", "新能源", 210, 214],
    ["隆基绿能", "新能源", 18, 17.2],

每一行顺序固定：股票名称、行业、开盘价、收盘价。

第一步 Recap

从数字，到一句人话

  • for 让同一套计算处理多只股票。
  • if / else 决定文字写“上涨”还是“下跌”。
  • format() 把名称、行业、涨跌额、涨跌幅塞进模板。

第二步

生成下跌股票风险提示

隆基绿能（新能源）今日下跌 0.8 元，跌幅 4.44%。

第二步 Recap

筛选，是按问题选择信息

  • 同一批数据，不同目标会留下不同结果。
  • if 可以决定哪一条报告留下来。
  • 程序的价值不只是计算，也包括帮人筛掉暂时不需要的信息。

从屏幕输出，到交付物

用真实数据做一份观察报告

问题：给几只股票的实时数据，能不能写出一段靠谱的市场观察？

案例路线

先拿到数据，再决定怎么说

第一关：数据入口

真实数据通常有四种入口

手工输入适合小数据、课堂练习、临时验证。
文件读取适合 Excel、CSV、txt 这类已经整理好的数据。
API网站或系统专门留给程序的数据入口。
爬虫网页本来给人看，程序去页面里把数据抠出来。

真实工作里，常见顺序是：先找数据文件，再找 API，最后才考虑爬虫。

API 像什么？

像餐厅的点菜窗口

你告诉它：我要哪只股票、哪一天、哪些字段。
它返回给你：价格、涨跌幅、成交额这些数据。

程序看到的通常不是网页，而是结构化数据。

课堂讨论

哪些服务背后更像有 API？

  • 淘宝、天气、股票、地图、外卖，哪些更像是背后有 API？
  • 为什么很多网站愿意提供 API，而不是让别人来爬网页？
  • 如果页面改版了，爬虫和 API 哪个更容易坏？

第三关：真实拉取

Python 也能像浏览器一样访问数据

发请求程序拿着一个网址，去问数据服务要结果。
拿回来服务返回一包有结构的数据，不是网页截图。
看字段里面会写清楚股票代码、价格、涨跌幅、成交量。
做报告程序再把这些字段整理成人能读懂的话。

真实 API 代码

import urllib.request
import json

url = (
    "https://www.alphavantage.co/query?"
    "function=TOP_GAINERS_LOSERS&apikey=demo"
)

response = urllib.request.urlopen(url, timeout=10)
text = response.read().decode("utf-8")
result = json.loads(text)

stocks = result["most_actively_traded"][:5]
for stock in stocks:
    ticker = stock["ticker"]
    price = stock["price"]
    percent = stock["change_percentage"]
    volume = stock["volume"]
    print(ticker, price, percent, volume)

真实数据的粗糙感

JSON 也要先认字段

  • json.loads(text)：把 JSON 文字变成 Python 数据。
  • result["most_actively_traded"]：先找到最活跃股票列表。
  • stock["ticker"]：股票代码。
  • stock["price"]、stock["change_percentage"]、stock["volume"]：价格、涨跌幅、成交量。

看到数据以后

先看列，再决定问题

先认列

  • 一共有多少行？
  • 每一列是什么意思？
  • 哪些列适合排序？
  • 哪些列适合分组？

列的例子

  • 名称：字符串，比如“贵州茅台”。
  • 开盘价：小数，比如 1709.00。
  • 成交额：数字，适合排序。
  • 行业：类别，适合分组。

分组就是按同一个字段把数据放在一起看，比如按行业分成“白酒”“新能源”“银行”。

现场问题

这份榜单能支持什么结论？

  • “最活跃交易”这个口径，适合回答什么问题，不适合回答什么问题？
  • volume 是成交股数；如果要比较资金活跃度，还缺哪一步计算？
  • 低价标的的涨跌幅容易很夸张，写报告时怎么避免被它带偏？
  • 如果同一段代码昨天能跑、今天失败，排查顺序应该是什么？

参考答案

先把结论边界说清楚

  • 它适合看“哪些标的今天交易很活跃”，不适合直接判断“哪些最值得买”。
  • volume 只是成交股数；比较资金活跃度，至少还要乘上价格。
  • 低价标的涨跌幅容易夸张，报告里要同时看价格、成交量和标的类型。
  • 代码昨天能跑今天失败，先查网络、接口状态、返回内容，再查自己代码。

所以呢

真实数据不是刚好为课堂准备的

  • 拿到数据以后，第一步是看列名和含义。
  • 第二步才是决定问题：排序、筛选、分组，还是生成报告。
  • 接口偶尔失败也很正常，网络、权限、数据源都可能影响结果。
  • 真实工作里，先判断“数据靠不靠谱”，再判断“结论好不好”。

第四关：提出问题

一只股票，能把平均数带飞

SOXS   +11.91%
HCWB  +262.02%
TZA    +7.02%
MRNO   +94.24%
HUBC   -8.74%

如果直接算平均涨幅：
这组股票平均上涨 73.29%。

问题在哪

73.29% 听起来很猛，但代表谁？

平均数

把所有涨跌幅加起来再平均，很容易被极端值拉高。

中位数

从小到大排，中间那个是 11.91%，更像“典型水平”。

问题不是平均数错了，而是它回答的不是“多数股票大概涨多少”。

怎么写报告

极端值要单独交代

差一点这组股票平均上涨 73.29%。
稳一点这组股票涨跌差异很大，平均值被 HCWB 的 262.02% 明显拉高。
再稳一点如果描述“典型表现”，中位数 11.91% 比平均数更合适。
关键先说明异常值，再下结论。

成交额怎么看

同样涨跌，放量和缩量含义不同

放量上涨更多资金参与上涨，走势更有分量。
缩量上涨价格涨了，但参与度不高，说服力弱一些。
放量下跌下跌里有大量交易，可能代表抛压或分歧很大。
缩量下跌价格跌了，但交易冷清，先看是否只是短期缺少买盘。

涨跌幅看方向和幅度，成交额看这次变化有多少资金参与。

第五关：写成报告

两个真实案例：整体和局部可能相反

市场报告最有意思的地方，常常不是“涨还是跌”，而是哪里跌、哪里没跌。

历史案例 1

2020-02-03：A 股大跌，但医药逆势

上证综指收跌 7.72%。
深证成指收跌 8.45%。
但医药相关股票领涨，20 多家公司涨停。

整体市场很弱，但疫情相关板块反而被资金关注。

历史案例 2

2025-01-27：DeepSeek 冲击美股科技股

纳斯达克指数跌 3.1%。
英伟达跌近 17%，市值蒸发约 5890 亿美元。
但道琼斯指数反而上涨 0.7%。
这不是“美股全跌”，而是 AI 科技股冲击更明显。

同一天里，不同指数、不同板块，可能讲的是完全不同的故事。

一起检查 AI

AI 写完以后，先对三件事

数字名称、涨跌幅、成交额有没有抄错。
范围它说的是这几只股票，还是整个市场。
原因原始数据里没有原因，就先不要写“因为”。
用词“偏弱”“活跃”“分化”这些词，和数据能不能对上。

真实案例

伯克希尔 A：一眼看上去跌没了

2024 年 6 月 3 日，伯克希尔 A 一度显示：
627400 美元 -> 185.10 美元，跌 99.97%。

但 B 类股没有同步暴跌，多只股票也同时异常停牌。
……

答案揭晓

不是公司一夜归零，是数据出错

后来纽交所确认：
这是价格数据技术问题。

伯克希尔 A 恢复交易后，价格很快回到正常区间。

这个案例的重点不是“跌得多”，而是：
看到离谱数字，要先怀疑数据质量。
