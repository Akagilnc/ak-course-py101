## 章节页

`#1 从数据到报告`

How to turn data into a report?

L2 已经能批量计算；L3 让结果变成给人看的文字。

## 前置知识：代码里的小数据表

这节课先不读外部文件。直接把几只股票写在代码里：

```python
stocks = [
    ["贵州茅台", "白酒", 1709, 1705],
    ["五粮液", "白酒", 150, 153],
    ["宁德时代", "新能源", 180, 174],
    ["比亚迪", "新能源", 210, 214],
    ["隆基绿能", "新能源", 18, 17.2],
]
```

这是一张很小的表：

- 外层 `stocks` 是一个 list。
- 里面每一行也是一个 list。
- 每一行的顺序固定：股票名称、行业、开盘价、收盘价。

比如第一行：

```python
stock = ["贵州茅台", "白酒", 1709, 1705]

name = stock[0]
industry = stock[1]
open_price = stock[2]
close_price = stock[3]
```

## 主例子：从股票数据到风险报告

这个动手例子分三步走。第一步完整写出来，后面两步都在第一步基础上小改。

### 第一步目标：给每只股票生成一句简报

把每只股票从一行数据，变成一句人能读懂的简报。

- 原始数据：`["贵州茅台", "白酒", 1709, 1705]`
- 程序加工：算涨跌额、涨跌幅
- 输出文字：`贵州茅台（白酒）今日下跌 4 元，跌幅 0.23%。`

### 前置知识：报告模板

```python
template = "{}（{}）今日{} {} 元，{} {}%。"
```

这句话里有 6 个 `{}`，后面就要放 6 个值。

### 第一步代码

```python
stocks = [
    ["贵州茅台", "白酒", 1709, 1705],
    ["五粮液", "白酒", 150, 153],
    ["宁德时代", "新能源", 180, 174],
    ["比亚迪", "新能源", 210, 214],
    ["隆基绿能", "新能源", 18, 17.2],
]

for stock in stocks:
    name = stock[0]
    industry = stock[1]
    open_price = stock[2]
    close_price = stock[3]

    change = round(close_price - open_price, 2)
    percent = round(change / open_price * 100, 2)

    if change > 0:
        direction = "上涨"
        change_text = change
        percent_name = "涨幅"
        percent_text = percent
    else:
        direction = "下跌"
        change_text = 0 - change
        percent_name = "跌幅"
        percent_text = 0 - percent

    template = "{}（{}）今日{} {} 元，{} {}%。"
    report = template.format(
        name, industry, direction, change_text, percent_name, percent_text
    )
    print(report)
```

### 第一步标准输出

```text
贵州茅台（白酒）今日下跌 4 元，跌幅 0.23%。
五粮液（白酒）今日上涨 3 元，涨幅 2.0%。
宁德时代（新能源）今日下跌 6 元，跌幅 3.33%。
比亚迪（新能源）今日上涨 4 元，涨幅 1.9%。
隆基绿能（新能源）今日下跌 0.8 元，跌幅 4.44%。
```

### 所以呢

- L2 的输出更像“程序结果”。
- L3 的输出开始像“给人看的报告”。
- 同样是数字，换一种表达方式，读者的理解成本会低很多。
- 这里没有用新函数，只是在 `if` 里面准备更适合展示的文字。

## 第二步：只保留下跌股票

### 目标

报告不是把所有内容都倒出来。  
如果这份报告的目标是提醒风险，那就只保留下跌股票。

### 前置知识：append()

```python
risk_reports = []

risk_reports.append("贵州茅台下跌")
risk_reports.append("宁德时代下跌")

print(risk_reports)
```

输出：

```text
['贵州茅台下跌', '宁德时代下跌']
```

`append()` 的意思是：把一条新内容放进 list 的最后。

### 第二步代码

```python
stocks = [
    ["贵州茅台", "白酒", 1709, 1705],
    ["五粮液", "白酒", 150, 153],
    ["宁德时代", "新能源", 180, 174],
    ["比亚迪", "新能源", 210, 214],
    ["隆基绿能", "新能源", 18, 17.2],
]

risk_reports = []

for stock in stocks:
    name = stock[0]
    industry = stock[1]
    open_price = stock[2]
    close_price = stock[3]

    change = round(close_price - open_price, 2)
    percent = round(change / open_price * 100, 2)

    if change < 0:
        down_change = 0 - change
        down_percent = 0 - percent
        template = "{}（{}）今日下跌 {} 元，跌幅 {}%。"
        report = template.format(name, industry, down_change, down_percent)
        risk_reports.append(report)

for report in risk_reports:
    print(report)
```

### 第二步标准输出

```text
贵州茅台（白酒）今日下跌 4 元，跌幅 0.23%。
宁德时代（新能源）今日下跌 6 元，跌幅 3.33%。
隆基绿能（新能源）今日下跌 0.8 元，跌幅 4.44%。
```

### 所以呢

- 筛选不是偷懒，是根据问题选择信息。
- 如果目标是风险提示，上涨股票可以先不显示。
- 程序的价值不只是“算”，还包括“帮人筛掉不相关信息”。

## 第三步：把风险提示写入 report.txt

### 目标

前两个例子都是打印在屏幕上。  
这次让程序生成一个文件：`report.txt`。

这个文件不需要提前准备，程序会自己创建。

### 前置知识：写文件

```python
file = open("report.txt", "w", encoding="utf-8")
file.writelines(risk_reports)
file.close()
```

- `"w"` 表示写入。
- 如果 `report.txt` 不存在，程序会创建它。
- 如果 `report.txt` 已经存在，旧内容会被清空。
- `writelines()` 会把 list 里的每一条文字写进去。

### 第三步代码

```python
stocks = [
    ["贵州茅台", "白酒", 1709, 1705],
    ["五粮液", "白酒", 150, 153],
    ["宁德时代", "新能源", 180, 174],
    ["比亚迪", "新能源", 210, 214],
    ["隆基绿能", "新能源", 18, 17.2],
]

risk_reports = []

for stock in stocks:
    name = stock[0]
    industry = stock[1]
    open_price = stock[2]
    close_price = stock[3]

    change = round(close_price - open_price, 2)
    percent = round(change / open_price * 100, 2)

    if change < 0:
        down_change = 0 - change
        down_percent = 0 - percent
        template = "{}（{}）今日下跌 {} 元，跌幅 {}%。\n"
        report = template.format(name, industry, down_change, down_percent)
        risk_reports.append(report)

file = open("report.txt", "w", encoding="utf-8")
file.writelines(risk_reports)
file.close()
```

### 运行后得到的 `report.txt`

```text
贵州茅台（白酒）今日下跌 4 元，跌幅 0.23%。
宁德时代（新能源）今日下跌 6 元，跌幅 3.33%。
隆基绿能（新能源）今日下跌 0.8 元，跌幅 4.44%。
```

### 所以呢

- 屏幕输出是临时看的。
- 文件输出是可以留下来、转发、继续加工的。
- `\n` 很重要：没有它，几条报告会挤在同一行。
- 这一步开始，程序就不只是“算给自己看”，而是在生成一个交付物。

## 后半模块 1：数据来源不只有爬虫

### 目标

很多人一听“从网上拿数据”，第一反应就是爬虫。  
但真实工作里，更常见的顺序通常是：先找数据文件，再找 API，最后才考虑爬虫。

### 四种数据来源

```text
手工输入：适合小数据、课堂练习、临时验证。

文件读取：适合 Excel、CSV、txt 这类已经整理好的数据。

API：网站或系统专门留给程序的数据入口。

爬虫：网页本来是给人看的，程序去网页里把数据抠出来。
```

### API 像什么？

API 有点像餐厅的点菜窗口：

```text
你告诉它：我要哪只股票、哪一天、哪些字段。
它返回给你：价格、涨跌幅、成交额这些数据。
```

程序看到的通常不是网页，而是结构化数据。

### 一个 API 请求大概长这样

```text
https://api.example.com/stock?symbol=600519&date=2026-05-15
```

这里可以先看懂三个部分：

- `api.example.com`：去哪一个数据服务拿数据。
- `symbol=600519`：股票代码。
- `date=2026-05-15`：要哪一天。

### API 和爬虫的区别

```text
API：对方本来就准备给程序读，字段通常比较清楚。

爬虫：对方页面主要给人看，程序要自己从页面里找数据。
```

爬虫有它的场景，但它更容易遇到页面改版、登录限制、反爬规则。  
真实项目里，能找到 API 的时候，通常先看 API。

### 课堂讨论

- 淘宝、天气、股票、地图、外卖，哪些更像是背后有 API？
- 为什么很多网站愿意提供 API，而不是让别人来爬网页？
- 如果页面改版了，爬虫和 API 哪个更容易坏？

### 所以呢

- 数据分析的第一步，常常不是写公式，而是找到可靠数据来源。
- API 是程序获取数据的一种常见入口，和爬虫不是一回事。
- 爬虫是补充办法，不是数据获取的唯一入口。

## 后半模块 2：用 dict 读结构化数据

### 目标

前半一直在用 list。  
API 返回的数据经常更像 dict，所以这里单独认识一下。

### API 返回的数据可能长这样

```text
{
  "name": "贵州茅台",
  "industry": "白酒",
  "open": 1709,
  "close": 1705,
  "amount": 123456789
}
```

这看起来像一张小卡片：左边是字段名，右边是具体值。  
这就是 dict 经常出现的样子。

### 前置知识：dict

前面学过 list。  
list 是按位置取值，dict 是按名字取值。

```python
stock_list = ["贵州茅台", "白酒", 1709, 1705]

stock_dict = {
    "name": "贵州茅台",
    "industry": "白酒",
    "open": 1709,
    "close": 1705,
}

print(stock_list[0])
print(stock_dict["name"])
```

可以先看三个特征：

- 外面是 `{}`。
- 每一项都有一个名字，比如 `"name"`、`"close"`。
- 名字和值之间用 `:` 连接。

输出：

```text
贵州茅台
贵州茅台
```

### 为什么 API 经常像 dict？

真实数据里，字段很多。  
如果只靠位置，`data[0]`、`data[1]`、`data[9]` 很容易看晕。

dict 更像人读得懂的表格：

```python
print(stock_dict["name"])
print(stock_dict["close"])
```

这里不用数第几个位置，直接说要哪个字段。

### `[]` 取值

```python
stock = {
    "name": "贵州茅台",
    "close": 1705,
}

print(stock["name"])
print(stock["close"])
```

输出：

```text
贵州茅台
1705
```

这种写法很直接：确定有这个字段，就用 `[]`。

如果字段名写错，程序会直接停下来：

```python
print(stock["price"])
```

这适合用在“字段必须存在”的地方。错了就早点暴露问题。

### `get()` 取值

```python
stock = {
    "name": "贵州茅台",
    "close": 1705,
}

print(stock.get("name"))
print(stock.get("price"))
```

输出：

```text
贵州茅台
None
```

`get()` 的特点是：取不到时，程序可以继续往下走。

也可以给一个默认值：

```python
print(stock.get("price", "没有这个字段"))
```

输出：

```text
没有这个字段
```

### `[]` 和 `get()` 的区别

```text
stock["name"]
确定这个字段一定存在，写错就让程序报错。

stock.get("name")
不确定字段在不在，先安全地取出来看看。
```

真实 API 数据有时候字段会缺失。  
这时候 `get()` 比直接用 `[]` 更稳。

## 后半模块 3：现场看一次真实数据

### 目标

这一段由老师演示即可，学生只看结果。  
重点不是学会 API 怎么写，而是第一次看到：真实数据可以由程序直接取回来。

### 演示方式

```python
import urllib.request

codes = ["sh600519", "sz000858", "sz300750", "sz002594", "sh601398"]
url = "https://hq.sinajs.cn/list=" + ",".join(codes)

request = urllib.request.Request(
    url,
    headers={
        "User-Agent": "Mozilla/5.0",
        "Referer": "https://finance.sina.com.cn/",
    },
)

response = urllib.request.urlopen(request, timeout=10)
text = response.read().decode("gbk")

for line in text.splitlines():
    data = line.split('"')[1].split(",")
    name = data[0]
    yesterday_close = float(data[2])
    current_price = float(data[3])
    amount = float(data[9])
    percent = round(
        (current_price - yesterday_close) / yesterday_close * 100,
        2,
    )
    print(name, current_price, percent, amount)
```

这段代码不用学生抄。  
老师现场运行，让大家看到今天真实市场数据长什么样。

这里有几个地方比前半复杂，反而很真实：

- `codes`：这次想看的股票代码。
- `decode("gbk")`：这个接口返回的是 GBK 编码，不是 UTF-8。
- `split(",")`：接口返回的是一长串文字，需要按逗号拆开。
- `data[2]`：昨日收盘价。
- `data[3]`：当前价格。
- `data[9]`：成交额。

`User-Agent` 和 `Referer` 可以先不用细讲，只说一句：有些接口会看请求像不像正常浏览器访问。

### 看到数据以后先看什么？

- 一共有多少行？
- 每一列是什么意思？
- 哪些列是文字？
- 哪些列是数字？
- 哪些列适合排序？
- 哪些列适合分组？

### 现场问题

- 这几只股票里，谁跌得最多？
- 这几只股票里，谁成交额最大？
- 这两个“第一名”为什么可能不是同一只股票？
- 只看这几只自选股票，能不能代表整个市场？
- 如果 API 今天失败了，应该怪代码，还是先怀疑网络和数据源？

### 所以呢

- 真实数据通常不是“刚好适合上课”的样子。
- 拿到数据以后，第一步是看列名和含义。
- 第二步才是选择问题：排序、筛选、分组，还是生成报告。
- API 偶尔失败也很正常，这本身就是数据工作的现实。

## 后半模块 4：真实数据拿到以后，先问什么问题？

### 目标

数据本身不会告诉你重点。  
成年人看数据，真正有价值的是先把问题问对。

### 同一份股票数据，可以问很多问题

```text
今天涨得最猛的是谁？

今天成交最活跃的是谁？

有没有涨幅很大但成交额很小的股票？

有没有成交额很大但涨跌不明显的股票？

这些自选股票里，是普遍同涨同跌，还是表现分化？

如果只看几只自己选的股票，会不会误判整体市场？
```

### 课堂讨论

- “涨幅最大”一定最值得关注吗？
- “成交额最大”一定代表最有机会吗？
- 如果一只股票涨了 10%，但成交额很小，你会怎么理解？
- 如果一只股票成交额很大，但只涨了 0.2%，你会怎么理解？

### 所以呢

- 数据分析不是把所有数字念出来。
- 好问题会决定你看哪几列、怎么排序、怎么筛选。
- 同一份真实数据，换一个问题，就会得到完全不同的报告。

## 后半模块 5：同一份真实数据，可以写出不同报告

### 目标

老师现场用同一份 API 数据，演示三种不同报告。  
这部分结果以现场数据为准，重点看报告目标的差异。

### 报告 1：市场速览

```text
今天这批数据里，先看整体数量：
上涨多少只，下跌多少只，平盘多少只。
```

这个版本回答：今天整体气氛怎么样？

### 报告 2：异动提示

```text
重点找涨跌幅靠前、成交额靠前、或者涨跌幅和成交额不匹配的股票。
```

这个版本回答：今天有哪些值得多看一眼的异常？

### 报告 3：给老板看的三行摘要

```text
第一行：整体情况。
第二行：最突出的上涨或下跌。
第三行：需要小心的口径和样本限制。
```

这个版本回答：30 秒内需要知道什么？

### 课堂讨论

- 哪一种报告最像新闻？
- 哪一种报告最像内部工作汇报？
- 哪一种报告最容易误导人？
- 如果你只允许报告写 3 行，最应该保留哪 3 个信息？

### 所以呢

- 报告不是数据的搬运，而是对问题的回答。
- 报告越短，越要说清楚筛选条件。
- 真实数据里，最危险的不是算错，而是把小范围结果说成大结论。

## 后半模块 6：让 AI 帮忙分析，但先给它边界

### 目标

AI 可以帮忙总结真实数据，但它很容易把“看起来像结论”的话说得太满。  
所以给 AI 数据之前，要先给它边界。

### 可以拍给 AI 的内容

把现场 API 结果复制给 AI，例如：

```text
下面是今天几只 A 股的实时数据，字段包括：
名称、最新价、涨跌幅、成交额。

请只根据这些数据做观察。
```

### 比较好的提问方式

```text
请根据这批数据写一段简短观察。
要求：
1. 只讨论我给你的这些股票
2. 只做数据观察，不给买卖建议
3. 区分“涨幅大”和“成交额大”
4. 如果样本太小，请明确说明
5. 最后列出你最不确定的地方
```

### 需要学生一起检查的地方

- AI 有没有把“部分股票”说成“整个市场”？
- AI 有没有把涨幅最大说成最值得买？
- AI 有没有忽略成交额？
- AI 有没有把样本限制说清楚？
- AI 有没有编造原始数据里没有的行业、公司、原因？

### 检查 AI 的锚点

前半已经写过一个最小版报告程序。  
检查 AI 时，就拿同样的规则对照：

- 数据范围是什么？
- 涨跌幅按什么口径算？
- 样本能不能代表整体？
- 输出有没有把金额和比例混在一起？
- 原始数据里没有的信息，AI 有没有自己补出来？

### 所以呢

- AI 很适合把数据结果组织成文字。
- 但 AI 不知道你这份数据是不是完整样本。
- 给 AI 的边界越清楚，输出越容易检查。
- 真正重要的不是“让 AI 说”，而是知道它哪里可能说过头。

## 后半模块 7：几个真正有用的数据分析词

### 目标

这节课不是证券分析课，但可以顺手学几个以后看数据都会用到的词。

### 口径：你到底在算什么？

前半代码用的是开盘价和收盘价：

```python
change = close_price - open_price
percent = change / open_price * 100
```

这表示：从开盘到收盘，价格变化了多少。  
它不是股票软件里最常见的“相对昨日收盘价”的涨跌幅。

同样叫“今天涨跌”，口径不同，数字就可能不同。

### 样本：你看的是全部，还是一小部分？

```text
老师现场取回来的几只自选股票。
```

这只能说“这次展示的数据里发生了什么”。  
如果要说“今天 A 股怎么样”，就要先确认数据范围是不是足够大。

### 金额：每股少了多少钱

```text
从现场数据里挑两只股票：
一只每股价格变化很大。
一只每股价格变化不大，但涨跌幅很明显。
```

按金额看，关注的是“每一股多了或少了多少钱”。  
这适合回答：价格绝对变化大不大？

### 比例：相对原价跌了多少

```text
同样从现场数据里看：
价格高的股票，变化 5 元可能只是小波动。
价格低的股票，变化 0.5 元可能已经很明显。
```

按比例看，关注的是“相对原价变化了多少”。  
这适合回答：严重程度更高的是谁？

### 所以呢

- 口径决定数字怎么算。
- 样本决定结论能说多大。
- 金额回答“少了多少钱”。
- 比例回答“相对严重不严重”。
- 很多数据争论，不是算错了，而是大家用的口径不一样。

## L3 Recap

- list 里可以放 list，用来表示一张小表。
- `for` 可以逐行处理这张小表。
- `format()` 可以把数据组织成自然语言。
- `append()` 可以先把需要的报告收集起来。
- `writelines()` 可以把报告写成文件。
- 报告不是把所有数字倒出来，而是围绕问题组织信息。
- API 是程序获取数据的一种常见入口，和爬虫不是一回事。
- AI 可以帮忙改写和分析，但要用数据、口径和样本范围约束它。
