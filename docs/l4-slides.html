#1 从 JSON 到文件

How to save structured data?

L3 看过接口返回的 JSON；L4 直接读取本地 JSON 文件。

认识 lesson4.json

先看结构，不急着写代码

文件lesson4.json 是已经整理好的疫情数据文件。
目标今天不处理全部内容，只找海外疫情汇总。
结果先生成一份文字报告，再生成一份 Excel 表。

这次只走一条路径

目标数据藏在 data 里面

raw_data整个 JSON 文件读进来以后得到的大 dict。
data业务数据主体，里面还有更新时间和很多列表。
othertotal海外疫情汇总，本节课第一次只处理它。
raw_data["data"]["othertotal"]

第一步

保存海外疫情汇总到 txt

拿数据从文件里找到海外疫情汇总。
挑指标选择累计确诊、现存确诊、累计死亡、累计治愈。
写成话把数字变成可以直接读的一段报告。
存下来生成 l4_oversea_report.txt，让结果离开屏幕。

第一步 Recap

旧方法继续有用

  • json.load(file) 负责把 JSON 文件读成 Python 数据。
  • raw_data["data"]["othertotal"] 是这次最关键的路径。
  • reports 仍然是 L3 的办法：先收集文字，再一次性写入文件。
  • txt 适合给人读，但不适合继续排序、筛选、做表格处理。

第二步

保存海外疫情汇总到 Excel

同样的数据，换成表格输出。

现存确诊7893000

pandas 是什么

Python 里的表格处理工具

前面我们已经会让 Python 读 JSON、写 txt。接下来，如果数据开始像“一张表”，就该 pandas 登场了。

Excel 表

一行一行、一列一列的数据。

订单 / 报名 / 流水

现实工作里最常见的数据形态。

pandas

帮 Python 更方便地处理这些表格数据。

今天先知道一件事：当数据开始像表格，pandas 就该登场。

下一页再认识它最常见的对象：DataFrame。

前置知识：DataFrame

先把它理解成 Python 里的表格

import pandas as pd

rows = [
    ["累计确诊", "35270206"],
    ["累计死亡", "1036359"],
]

df = pd.DataFrame(rows, columns=["指标", "数值"])

rows 是原材料，df 是已经有行和列的表。

to_excel()

把表保存成 Excel 文件

df.to_excel(
    "l4_oversea_report.xlsx",
    index=False,
    sheet_name="汇总"

文件名保存成哪个 xlsx
index=False不保存自动行号
sheet_name工作表名称

第二步 Recap

同一份数据，两种交付物

  • txt 是文字报告，适合直接阅读。
  • xlsx 是表格报告，适合继续加工。
  • 代码前半段没有变：还是读取 JSON，找到 total。
  • 输出方式变了：从 writelines() 换成 DataFrame 和 to_excel()。

案例 2 · 奶茶店订单

一张小表，可以回答很多问题

数据商品、单价、销量。
问题销量、单价、销售额，分别回答不同事情。
目标看懂指标不同，结论可能不同。

原始数据

先别急着算，先看问题

商品单价销量
珍珠奶茶123
柠檬茶104
拿铁182
  • 哪个产品销量最高？
  • 哪个产品单价最高？
  • 哪个产品销售额最高？

加一列销售额

答案开始变得不一样

商品单价销量销售额
珍珠奶茶12336
柠檬茶10440
拿铁18236

卖得最多、单价最高、销售额最高，不一定是同一个商品。

店长真正关心什么

问题不同，看字段就不同

  • 如果要备货，销量是不是最重要？
  • 如果要看收入，销售额是不是更重要？
  • 如果想知道哪个产品最赚钱，还缺什么数据？
  • 如果只看一天数据，能不能判断明天卖什么？

AI 可以帮哪一步？

帮你提出问题，而不只是回答问题

请根据下面这份奶茶店订单数据，提出 5 个值得分析的问题。

要求：
1. 区分“可以直接回答”和“需要更多数据才能回答”
2. 每个问题说明为什么值得问
3. 不要直接给经营建议

数据：
珍珠奶茶，单价12，销量3
柠檬茶，单价10，销量4
拿铁，单价18，销量2

可能得到的方向

AI 不只是回答，也能帮忙提问题

可以直接回答：
- 哪个产品销量最高？
- 哪个产品销售额最高？
- 总销售额是多少？

需要更多数据：
- 哪个产品利润最高？因为目前没有成本数据。
- 明天应该多备什么？因为还需要历史销量和库存数据。

所以呢

数据分析不是先把所有数字算出来

  • 先问对问题，再决定看哪些字段。
  • 同一张表，不同问题会得到不同重点。
  • AI 可以帮忙提出问题，区分“能回答”和“缺数据”。
  • pandas 后面会帮我们更快地筛选、计算、统计和导出。

案例 4 · 天气 API

结构化数据变成生活提醒

场景明天晚上有户外活动，要不要提醒大家带伞？
数据API 返回一段 JSON，不是网页。
目标找到关键字段，做不过度的判断。

API 返回的数据

程序拿到的是 JSON

{
  "city": "成都",
  "date": "2026-05-20",
  "forecast": [
    {"time": "09:00", "temperature": 22, "rain_probability": 20},
    {"time": "15:00", "temperature": 27, "rain_probability": 65},
    {"time": "21:00", "temperature": 23, "rain_probability": 80}
  ]
}

先看结构

路径仍然是 dict 和 list

city城市，成都。
date日期，2026-05-20。
forecast一个 list，里面每条是一个时间点。
路径weather["forecast"][0]["rain_probability"]

课堂问题

同一天，不同时间段结论可能不同

  • 上午出门，要不要带伞？
  • 下午出门，要不要带伞？
  • 晚上 8 点有户外活动，要不要提前提醒大家？
  • 如果只看上午天气，会不会误判？

数据判断

看哪个字段，取决于问题

09:00 降雨概率 20%，风险不高。
15:00 降雨概率 65%，风险明显升高。
21:00 降雨概率 80%，晚上户外活动风险较高。

AI 可以帮哪一步？

把结构化数据改写成活动提醒

请写一段活动提醒：明天晚上 8 点有户外活动。

要求：
1. 只根据给定数据
2. 说明主要参考哪个时间点
3. 数据不足就说明缺什么
4. 输出：结论、依据、提醒

参考输出

把数据变成可以发给人的话

结论：
明晚户外活动有较高下雨风险，建议提前准备雨具。

依据：
活动时间接近 21:00，该时间点降雨概率为 80%。

提醒：
目前只有三个时间点，没有更精细的小时预报，也没有降雨量信息，所以只能判断风险偏高。

所以呢

API 数据能支持提醒，但不能支持过度结论

  • API 数据通常是给程序读的，不是直接给人读的。
  • 人要先问：我要解决什么问题？看哪个字段？看哪个时间点？
  • AI 可以帮忙把数据变成提醒，但不能把 80% 降雨概率说成“一定下雨”。
  • 数据不足时，提醒里要说清楚还缺什么。

后半 Recap

现实信息进入程序前，需要先变成结构

  • 接龙、流水、订单这些现实数据，常常要先整理成字段。
  • 同一张表可以回答很多问题，但先要问清楚想知道什么。
  • 分类不是天然存在的，是按目的定规则。
  • API 返回的数据通常是给程序读的，要先找到关键字段。
  • AI 可以帮忙结构化、提问题、分类、改写提醒，但边界仍然由人决定。
